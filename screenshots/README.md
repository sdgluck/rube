# Screenshots

Every page of the admin UI, at two viewports, so a design review is always
looking at what the app currently renders rather than at a diff.

```sh
pnpm screenshots        # in Docker, then `git add screenshots`
pnpm screenshots:local  # faster, for iterating on shots — don't commit the result
```

`pnpm screenshots` runs the whole capture — mock Plex, server, Vite and Chromium
— inside the Playwright image, so it needs a Docker daemon. That is not
ceremony: the font rasteriser is part of the operating system, macOS draws
glyphs through CoreText and Linux through FreeType, and nothing inside Chromium
can reconcile the two. Pinning the OS is the only way these images mean the same
thing on someone else's machine.

`screenshots:local` skips the container and runs against your own Chromium. Much
faster while you are adding shots, and every pixel of text will differ from the
committed set, so regenerate properly before committing.

`desktop/` is 1440×900, `mobile/` is 430×932. Files are numbered in sidebar
order so the folder reads as a tour; the suffix is the state
(`03-collections-grid`, `03-collections-empty`). `manifest.json` describes each
shot in a line, and records the `uiHash` the pre-commit hook checks.

## Nothing here is real

The capture runs the real admin UI against a synthetic dataset and a mock Plex
server, never against your library. That is deliberate on three counts, and the
rule holds whether or not this repo is private:

- **Copyright.** Poster art is studio marketing material. These are gradients
  generated by `harness/posters.ts`, stamped `RUBE · DEMO`.
- **Other people's privacy.** `/users` and `/preview` show the real names of
  everyone you share a server with. Here they are five invented users.
- **Secrets.** Settings pages show hostnames and API keys. The seeded config
  points at `127.0.0.1` with a `demo-token`, and no API key is seeded at all.

The eight images the marketing site publishes come from the same run, so there
is only one path for a screenshot to reach the outside world and it starts from
fake data.

`harness/capture.ts` refuses to start unless `DATA_DIR` is its own throwaway
directory, so it cannot seed — or capture — a real database.

## Why the images are byte-stable

An unchanged page must produce an identical PNG. Otherwise every UI commit
rewrites all ~96 files and the folder becomes 20 MB of noise per commit instead
of a readable diff. Getting there took pinning:

| Source of drift                                                       | Fix                                                                                                                         |
| --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Relative times, server uptime                                         | One `FIXED_NOW` shared by the seeder, the server (`--import deterministic.mjs`) and the browser (`page.clock.setFixedTime`) |
| `Math.random` — Overlays picks its sample poster with it              | Seeded in both the server preload and a browser init script                                                                 |
| The cron scheduler writing job runs mid-capture                       | `TB_DISABLE_SCHEDULER=1`                                                                                                    |
| react-query polling repainting mid-screenshot                         | A `CaptureQueryClient` behind `VITE_TB_CAPTURE`, dropped from real builds                                                   |
| Spinners and shimmer                                                  | `reducedMotion` plus Playwright's `animations: "disabled"`                                                                  |
| Redacted secrets — the sentinel is randomised per process, by design  | No secrets in the fixtures                                                                                                  |
| Chromium's PNG encoder, which is not byte-stable for identical pixels | Re-encoded through `sharp`                                                                                                  |
| GPU raster jitter in shadow gradients                                 | `--disable-gpu`, `--force-color-profile=srgb`                                                                               |
| The host OS's font rasteriser — CoreText on macOS, FreeType on Linux  | The capture runs inside `mcr.microsoft.com/playwright`, tagged to match the installed driver                                |

Verify with two runs back to back: the second should report
`0 updated, 96 unchanged`.

## Limits

- **Same architecture.** The container fixes the operating system, which was the
  large difference. It does not guarantee that linux/arm64 and linux/amd64
  rasterise identically — probably they do, since FreeType's output isn't
  arch-dependent, but nobody has checked. If two machines ever disagree, pin
  `--platform` in `scripts/capture-docker.mjs` and regenerate once.
- **These are Linux screenshots.** Platform-conditional UI renders accordingly —
  the search hint reads `Ctrl+K` rather than `⌘K`, because that is what
  `modChord` returns off a Mac. Correct for the container, and worth
  remembering before filing it as a bug.
- **The hook proves a procedure ran, not that the pixels are right.** A capture
  against a stale mock still satisfies it. `manifest.json` records the
  Playwright and Chromium versions so a mass diff has an explanation.
- **Backend changes aren't covered.** `domains/**` and `apps/server/**` can move
  pixels, but including them would demand a capture on every backend commit, and
  a hook people route around with `--no-verify` — which also skips lint and
  typecheck — is worse than a narrower one. See `scripts/ui-hash.mjs`.
- Health shows only Plex as configured, because configuring the other
  integrations would mean seeding API keys.
